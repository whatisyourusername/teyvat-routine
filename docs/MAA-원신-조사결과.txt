Teyvat Routine v0.7 — 인식·입력 개선 조사
확인일: 2026-10-19

1. 실제 파일에서 확인한 원인과 한계
- 나무 등록 이미지 5장 중 상단 Y=21,42,49px인 이미지가 있었으나 구 버전 탐색은 상단 9%를 제외했다. 동일 구도에서도 후보 영역이 제외되는 구조였다.
- 구 버전은 9개의 크기만 비교했다. v0.7은 12% 간격의 크기와 기존 크기를 함께 탐색한다.
- 확인 이미지의 RGB 픽셀 차이에 민감하던 비교를 형태 상관도 중심으로 변경했다. 기본 기준 및 위치 허용치를 조정하고 개별 조절 UI를 추가했다.
- 로그에 '프로그램 또는 다른 창 클릭'으로 녹화가 멈춘 사례가 있다. 카메라 모드에서도 커서가 다른 창 위인지 검사하던 경로를 수정했다. 모든 중단의 원인이 이것이라고 단정할 수는 없다.
- 지도 워프 구간에 상대 이동만 기록된 사례가 있다. 메뉴/카메라 수동 모드가 화면 상태와 달랐을 가능성이 있어 Windows 커서 표시를 이용하는 자동 전환과 수동 해제를 제공한다.
- 실제 포커스 상실, 관리자 권한 차이, 절대형 Raw 입력 장치, 게임 자체 커서 등은 별도 원인이 될 수 있다. 진단 카운터를 로그에 남긴다.

2. MAA에서 참고한 것
공식 저장소: https://github.com/MaaAssistantArknights/MaaAssistantArknights
공식 작업 규격: https://docs.maa.plus/en-us/protocol/task-schema.html
- MAA는 템플릿·OCR·특징점 인식, 대상별 기준, ROI, 여러 템플릿을 지원한다. 일반 템플릿 기본 기준은 0.8이며 알고리즘마다 점수 의미가 다르다.
- next/onErrorNext/maxTimes와 전후 대기 시간으로 화면 상태에 맞춰 진행하거나 실패 경로를 선택한다.
- 설치된 v6.0.1의 resource/tasks/tasks.json에서도 0.65/0.7 같은 대상별 기준과 postDelay를 확인했다.
- 이번에는 형태 상관도, 기준 조절, 후보 점수 진단, 중복 후보 구분, 제한 시간과 연속 확인을 적용/유지했다. MAA 코드나 DLL을 복사하거나 연결하지 않았다.
- MAA의 에뮬레이터 좌표 입력을 원신 카메라에 그대로 적용할 수는 없다. 메뉴 좌표와 상대 카메라 이동을 구분해야 한다.
- OCR/SIFT/학습된 나무 검출기는 이번 버전에 포함하지 않는다. 원신의 큰 원근/가림/조명 변화는 추가 기준 이미지나 전문 검출 모델이 필요할 수 있다.

3. 원신 실시간 정보 조사
HoYoLAB API 래퍼와 공개 데이터 모델:
https://github.com/seriaati/genshin.py
https://seria.is-a.dev/genshin.py/reference/models/genshin/chronicle/notes/
- 확인한 Real-Time Notes 데이터는 레진, 일일 임무, 탐사 등이다. 이 목록은 전투 중 카메라 각도나 적 좌표를 제공하지 않는다. 비공식 래퍼이며 사용자 인증이 필요한 방식이다.
- 이번 조사에서 전투 카메라/월드 좌표를 제공하는 공식 공개 API는 찾지 못했다. 공식 인터페이스가 없다는 것을 절대적으로 증명한 것은 아니다.
BetterGI 공식 저장소: https://github.com/babalae/better-genshin-impact
- 영상 인식과 입력 모사, 미니맵 인식을 사용하는 공개 사례다. 모드의 존재만으로 안정적인 공식 전투 상태 인터페이스가 제공되는 것은 아니다.
- 이번 프로그램은 화면의 고정 기준물을 찾아 시작 시점을 정렬한다. 절대 방위나 좌표가 아니며, 전투 중간의 연속 방향 추적은 포함하지 않는다.
- 메모리 읽기/쓰기, DLL 주입, 패킷 가로채기 또는 안티치트 우회는 추가하지 않았다.

4. Windows 입력 근거
https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse
https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorinfo
- Raw 상대 이동은 커서 좌표와 구분되는 값이다. 입력 장치가 절대 좌표를 보내는 경우도 있어 진단에서 별도로 집계한다.
- GetCursorInfo는 Windows 커서 표시 상태를 읽는다. 게임 내부에서 따로 그린 커서를 판별하는 보편적인 인터페이스는 아니다.

5. 운영원칙 관련 확인
공식 공지: https://genshin.hoyoverse.com/en/news/detail/103714
- 공식 공지는 스크립트/서드파티 소프트웨어로 인위적인 게임 진행을 얻는 행위에 대해 제재할 수 있다고 명시한다.
- 처음 요청의 '운영원칙에 어긋나지 않는다'는 전제를 보장할 수 없다. 화면 인식 방식이라는 이유만으로 허용되는 것은 아니다.
- 이번 검증은 실제 게임 플레이/레진 소비 없이 코드와 저장 이미지로 수행했다.
